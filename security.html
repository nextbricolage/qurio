Security Policy

Last updated: 6 November 2026

Qurio Q&A for Confluence ("Qurio", "the app") is a 100% Atlassian Forge app published on the Atlassian Marketplace by nxb labs. It runs entirely on Atlassian Forge: there is no external backend, no server we operate, and no outbound network calls. All data is stored in Forge Storage inside the customer's own Atlassian Cloud instance and is encrypted at rest by the Atlassian platform.

Reporting a vulnerability

If you believe you have found a security vulnerability in Qurio, please report it privately — do not open a public GitHub issue.

  • Email: martinnxb@gmail.com
  • Please include: a description of the issue, steps to reproduce, affected version, and any proof-of-concept details.
  • We acknowledge reports within 2 business days and keep you updated on remediation progress.

Please give us a reasonable window to investigate and fix the issue before any public disclosure. We do not currently operate a paid bug-bounty program, but we credit reporters who responsibly disclose valid issues (with their consent).

Supported versions

The latest version published on the Atlassian Marketplace is the supported version and receives security fixes.

Our security practices

  • Architecture: 100% Forge. No external backend, no self-hosted servers, no external.fetch / egress permissions. Data lives only in Forge Storage within the customer's Atlassian Cloud instance (encrypted at rest; follows Atlassian data residency).
  • No sensitive data: we store only the Atlassian accountId — no passwords, tokens, emails, or usernames — and we never log credentials or secrets.
  • Source control: GitHub with MFA required. As a sole-developer project, changes are self-reviewed (diff review) and must pass automated security scans (CodeQL, Dependabot, npm audit) before a production deploy, following a documented pre-release checklist.
  • Automated scanning: CodeQL (SAST) on every push/PR and weekly; Dependabot (SCA) for dependency vulnerabilities; npm audit on dependencies.
  • SBOM: a CycloneDX Software Bill of Materials is generated per release for both the Forge resolver and the Custom UI SPA, so the full dependency inventory is auditable.
  • Secure coding: development follows the OWASP Top 10; all writes are validated server-side in the Forge resolver.

Incident response

We maintain a documented incident response plan. In the event of a confirmed security incident or critical vulnerability, we notify affected customers and Atlassian in line with Atlassian's Marketplace security policies.
